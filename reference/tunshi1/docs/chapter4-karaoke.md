## 播放和恢复

`karaoke-audio.js` 延迟创建唯一 KTV `HTMLAudioElement`，全曲试听和演唱挑战复用。新局加载专用挑战片段，从零秒播放，不再先加载完整歌曲再定位。小游戏时间/滚动/输入判定跟随片段实际 `currentTime`，不会让帧计时领先音乐；输入前也读取播放头。加载、定位、缓冲和播放被拦/失败时保持谱面进度，显示状态/重试按钮，不悄悄丢音符。重试在用户点击中调用 `play()`，从当前游戏时间对应的片段位置开始。加载或播放头十秒无进展，暂停音频并给出重试按钮，谱面不消耗。

游戏声音开关通过 `muted` 作用到原曲，不改变成绩或播放时间。P/暂停按钮、窗口失焦、切后台暂停；回到后台不自行恢复。选歌页、关闭面板、结算、放弃、刷新/新开游戏停掉并卸载当前录音，失效的 `play()` Promise 不能重新唤醒已退出的音乐。沿用现有被面板暂停的街区 BGM；移除 KTV 合成旋律和按键音，街机霓虹节拍仍有原电子节奏。

只有现有小游戏循环负责评分和画面。没有新 RAF/轮询计时器；全曲试听不维持连续 3D 渲染。歌词字幕未添加，因为用户未提供歌词文本，也未请求转写。

新进行中的局保存 `songId`、`audioVersion: 1`、完整谱面、命中、时间、费用和场所，客户端/生成 Worker 校验当前三个曲目与 track 一致；不保存媒体元素或任意音频 URL。TEST 不开发或验收旧档兼容；只验证当前版本的在途局。刷新/迁移只恢复游戏状态，实际续局点击后才加载/定位/播放，绝不第二次收费。

## 本轮卡住复现与修复

旧实现要求 seeked 到达时播放头与目标差值小于 0.05 秒；控制媒体实际复现 `target=18.805/currentTime=18.925/ready=false/chartTime=0`。现在新挑战不需要开局 seek，续局需发出过定位且已结束 seeking，允许播放头在事件到达前继续前进。加载元信息未准备好不会向旧资源定位，关闭/换歌的异步回调不重开音乐。

`node scripts/build-karaoke-excerpts.mjs` 可重建已提交的三份片段；常规 Site build 不依赖 FFmpeg。必须将 `-ss` 放在 `-i` 之后先解码再截取；输入侧快速定位会使《念豚师》与现有谱面错位。独立音乐测试逐首解码片段，对照原曲对应时间的解码波形（相关系数 >0.99），并验证新局无 seeked 仍开始、96 个真实按键命中、晚到续局事件及十秒加载重试。媒体 API 为替身，波形验证不等同人工听感验收。
