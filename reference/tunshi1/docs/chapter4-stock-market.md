# 股票开户、随身交易及剧情估价接口

2026-10-03 更新。仅本 TEST Site；基于发布 v52 调整日常行情。第四章已有五个剧情重估节点，主站没有改动。

## 玩家流程

首次在湘城证券营业部的行情终端按 E，选择「免费开户」。之后按 V 或顶部「交易」打开同一账户；V / Esc / 返回按钮关闭。室外、室内、驾驶和其他区域均可访问，正在对话、暂停或操作另一界面时不会叠加面板。资金来自个人钱包。买卖以点击时的实际报价结算，数量可选 1 / 5 / 10 股，或 1/4 仓 / 半仓 / 全仓。比例买入以当前钱包可买的股数为基数，再受剩余持仓额度限制；比例卖出以当前选中股票的持仓股数为基数，全部向下取整，不下零股单。数量和金额随报价变化，下单重新计算，单股持仓上限 10000。交易记录和迁移校验允许单次 1–10000 股，兼容旧 1 / 5 / 10 股记录。

旧存档保留全部报价、持仓、成本和交易记录；缺少账户字段且已有持仓或交易记录时迁移为已开户。未交易的旧玩家正常去营业部开户。新字段仍属于 `game.cityLeisure` version 1，通过可选字段保持旧迁移文档有效。

## 行情与暂停

- `market.clock`：独立市场游玩秒数。正常游玩或已开户的交易面板可见时推进；不会推动街区、角色、车辆、恢复 buff 或论坛冷却。
- `market.quote`：每秒一次的报价序号；`market.period` 保留旧值，此后作为普通商圈消息的累计计数，不再决定固定 90 秒公告或公司/方向轮换。
- 五家公司使用下节的连续随机行情；消息、公共市场和各公司各自的波动共同作用。没有真实证券行情或外部 API。
- 行情直接更新文字、买卖金额、持仓浮盈和原 2D 图表，不替换整个面板；选择、焦点、滚动和展开记录不会因报价重置。
- 使用现有 60 FPS 帧链，不新增 RAF / interval；交易时世界暂停，持续报价不会连续重画 3D。
- 隐藏页面停止计时，返回自动继续；没有离线时间补算。交易、事件、关闭即时保存，普通报价每五秒保存一次。

## 随机波动模型

旧版每秒用 `quote * 7919 + 19` 重启简单随机数，邻近种子产生明显相关走势；消息固定每 90 秒轮换涨跌与公司。本轮移除这两条规律。

- 每份新市场用一次随机种子初始化连续 sfc32 流，之后只推进已保存的四个整数状态；打开/关闭交易面板不重新播种。正常读档、导入、刷新恢复当前随机流与波动状态。
- 公共市场冲击加上每家公司不同的敏感度和独立正态冲击，五只股票有联动，也有自己的路径。使用对数收益生成正价格，仍按分成交、保留最近 30 个报价。
- 30–180 秒的不定长市场阶段改变波动基准和轻微方向偏好；GARCH 风格的方差记忆让大冲击后的一段时间仍然活跃，而平静时逐渐缩小。普通消息间隔随机为 20–480 秒，公司/商圈及利好/利空随机选择，消息冲击通常比普通报价大。
- 很弱的对数估价回归与价格边界控制长期极端值；不会把剧情重估压回旧基础价 2.2 倍上限。五个剧情事件仍通过稳定 ID 原子生效、永久保存倍率且不重复应用，普通消息不占剧情事件去重表。
- `market.model` 是 v1 存档的可选对象，包含版本、随机流、公共/个股方差、当前阶段和消息剩余秒数。旧档缺少模型时，从已有报价、历史、时钟和事件稳定生成一次初始模型，不重放过去、不改价格/持仓/成本。同一旧档反复读入产生相同后续行情。

波动聚集方向参考 [Engle 的 ARCH/GARCH 说明](https://pages.stern.nyu.edu/~rengle/ARCHGARCH.pdf)；随机阶段、新闻、系数和秒级幅度是本游戏的节奏选择，未用真实行情校准。16 组固定种子、144000 条秒级模拟收益的自动检查结果：标准差约 1.10%，绝对变化 95 分位约 2.26%，绝对收益相邻相关约 0.21，平均公司间相关约 0.30，收益相邻方向相关接近 0。这里只是可重复的游戏样本，不是现实证券的统计估计。

客户端与生成 Worker 同步校验随机状态整数范围、有限方差、阶段/消息计时及五家公司状态；迁移不剥离新增字段。每秒只处理五家公司，沿用现有报价/存档/RAF 节奏。

## 后续剧情调用

剧情运行时使用共享 `api.marketEvent(event)`；当前接线为 `chapter.api.marketEvent = event => leisure.applyMarketEvent(event)`。返回 `true` 表示首次生效，`false` 表示重复、无效或事件容量已满。调用者不直接修改报价、钱包或 holdings。

```js
api.marketEvent({
  id: 'c4_company_partnership_completed',
  label: '江湾饮品公布重大合作',
  changes: {
    river_drinks: {valuationMultiplier: 3, priceMultiplier: 2.5},
    neon_mobility: {valuationMultiplier: 0.4}
  }
});
```

这是接口示例，当前七任务使用另外五个固定事件，见剧情文档。`id` 必须是剧情阶段固定 ID，不用每次运行新生成的随机值。所有公司变更全部验证成功后一起生效；重试、读档或迁移后，同一个 ID 不会再次改变市场。

| 字段 | 含义 |
| --- | --- |
| `id` | 非空稳定事件 ID，最长 80 字符 |
| `label` | 面板/论坛最新公司消息，最长 200 字符 |
| `changes` | 至少一家已知公司，使用下方稳定 ID |
| `valuationMultiplier` | 乘到持久公司估价上，影响此后的价格回归 |
| `priceMultiplier` | 立即乘到当前成交价格上；省略时跟随估价倍率 |

两种倍率都可使用 0.01–100 的正数；仅给 `priceMultiplier` 时，估价也默认使用同一倍率。若只需短期冲击而不改变长期估价，明确传 `valuationMultiplier: 1`。累计估价倍率须在 0.01–100 内，超出时整条事件拒绝。价格保留两位小数、范围 ¥0.01–¥10000000；不再受旧基础价 2.2 倍上限压回。反向剧情使用新的稳定 ID 和反向倍率。

已生效事件保存到 `market.events`，最多 128 条；到达容量时拒绝新事件，保留全部去重记录。每条保留 ID、消息、时间和公司变更；存档迁移验证这些记录。`market.valuations` 保存所有公司的累计估价倍率。
